# intp-shorts 공용 디자인 시스템

이 폴더는 새로 만든 디자인이 아니라, **기존 숏츠 1~3편(사용자가 업로드한
`롱폼02_숏폼01/02/03.mp4`)을 픽셀 단위로 분석해서 코드로 고정한 것**입니다.
이후 숏츠(05, 06, ...)를 만들 때도 이 3개 파일만 import 해서 재사용하세요.

## 분석 방법

1. `ffmpeg`로 세 영상의 0.02 / 0.10 / 0.20 / ... / 0.98 지점 프레임을 PNG/JPG로 추출
2. 프레임을 직접 확인해서 레이아웃/등장 방식(포맷)을 파악
3. Pillow로 배경색, 강조색(노란 형광펜, 레드+피치), 회색 톤을 픽셀 샘플링
4. `ffprobe`로 해상도(1080x1920, 30fps), 오디오 스펙(AAC, 44.1kHz, stereo)을 확인
5. `silencedetect`/`volumedetect`로 오디오 특성 확인(아래 참고)

## 확인된 포맷 (변경하지 말 것)

- **화면비/해상도**: 9:16, 1080x1920, 30fps
- **레이아웃**: 흰 배경 위에서 "커뮤니티 글을 스크롤해서 읽는" 형태.
  카메라 줌/흔들림/화려한 전환 없음. 문단이 순서대로 나타나고, 화면이
  부드럽게 위로 스크롤되며 다음 문단을 보여줌.
- **상단바**: `‹ INTP 게시판` (굵게) + 우측 `⋮` 케밥 아이콘. 회색(#6E6E6E대) 아이콘.
- **제목 카드**: 굵은 2줄 제목 + `○○ · 방금 전 · 조회 N` 메타 + 얇은 구분선.
  (숏폼04는 사용자의 "인트로 금지" 지시로 이 블록을 생략하고 바로
  본문 훅 문구로 시작함 — `tokens.css`/`post-ui.css`의 `.title-card`는
  향후 숏츠를 위해 그대로 남겨둠)
- **본문 문단**: 검정~진회색(#141414~#2B2B2B), 문단 사이 여백, 한 화면에
  1~2줄만 노출
- **강조 1 — 노란 형광펜 인용구**: 굵은 텍스트 + 배경 `#FDF3AE`. 주로
  따옴표로 된 반문("왜...?", "~인가?")에 사용
- **강조 2 — 확대된 굵은 문장**: 박스 없이 글자만 커지는 강조. 짧고
  임팩트 있는 단정문에 사용
- **강조 3 — 레드 키워드 + 피치 하이라이트**: 문장 전체는 굵은 검정이고,
  핵심 단어/구절만 레드(`#E3492B`) 텍스트 + 배경 `#FBD9C6`. 주로 글의
  결론/펀치라인에 사용
- **댓글 섹션**: 본문이 끝난 직후 `💬 댓글` 헤더(위에 구분선) → 댓글 카드
  순서대로 등장. 카드 구성: 원형 회색 아바타(말풍선 아이콘) + `○○`
  아이디 + `👍 N` + 댓글 본문. 카드 사이 얇은 구분선. 댓글이 동시에
  겹쳐서 나오는 연출은 없음(한 번에 하나씩 순서대로).
- **영상 종료**: 마지막 댓글이 보인 직후 바로 컷. 구독 유도 문구나
  아웃트로 카드 없음.
- **오디오**: AAC 44.1kHz 스테레오. `mean_volume≈-24dB`, `max_volume≈-2.8dB`,
  0.3~0.5초 이하의 짧은 무음만 간헐적으로 존재 → 내레이션(TTS로 추정) +
  낮은 배경음(bed)이 거의 끊김 없이 깔려있는 구성으로 추정.
  (이번 작업에는 실제 오디오 소스가 없어 배경음/보이스 파일 자체는
  포함하지 못함. `shorts/롱폼02_숏폼04/audio/README.md` 참고)

## 파일

- `tokens.css` — 색상/폰트/크기 CSS 변수
- `post-ui.css` — 상단바/제목카드/문단/강조/댓글 컴포넌트 스타일
- `post-ui.js` — `timeline.json` 기반 재생 엔진(`ShortPlayer`). `renderAtTime(t)`가
  순수 함수처럼 동작해서 Playwright로 프레임 단위 결정론적 캡처가 가능함
