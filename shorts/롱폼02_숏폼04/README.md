# 롱폼02_숏폼04 — "INTP가 우연히 잘된 일을 그냥 못 넘기는 이유"

롱폼 2편 파생 숏츠 4편째. 기존 숏츠 1~3편과 같은 디자인 시스템
(`../../shared/design-system/`)을 그대로 재사용하고, 이 폴더에는
이번 숏폼 고유의 대본/타이밍/댓글만 들어있습니다.

**렌더링은 진행하지 않았습니다.** 편집 프로젝트(코드 + 타임라인)만
완성된 상태이며, 실제 mp4를 만들려면 `audio/README.md`를 따라 음성을
넣고 `render/render.sh`를 실행해야 합니다.

---

## 1. 생성/수정한 파일

```

shared/design-system/post-ui.js                  (신규 — timeline.json 기반 재생 엔진)
shared/design-system/README.md                   (신규 — 추출 근거/방법론 문서)

shorts/롱폼02_숏폼04/timeline.json                 (신규 — 대본/타이밍/댓글 큐)

shorts/롱폼02_숏폼04/audio/README.md               (신규 — 오디오 준비 안내, 오디오 파일 자체는 없음)
```

기존 숏츠 1~3편 관련 파일은 이 repo(`dsf900601/intp-shorts`)에 애초에
존재하지 않았습니다(업로드된 mp4 3개는 참고용 레퍼런스로만 분석했고,
git에는 커밋하지 않았습니다 — 자세한 내용은 이 파일 맨 아래 "확인 사항" 참고).

## 2. 예상 영상 길이

**34.2초** (목표 30~35초 범위 안).

> `timeline.json`의 각 cue `duration`은 실제 내레이션 오디오가 없는
> 상태에서 대본 글자 수 기준으로 잡은 **임시 타이밍**입니다. 실제 음성을
> 넣고 `node scripts/fit-timeline-to-audio.mjs`를 돌리면 오디오 실제
> 길이에 맞춰 자동으로 재배분되고, 그 결과도 30~35초 범위를 벗어나면
> 스크립트가 경고를 출력합니다.

## 4. 렌더링 명령어 (아직 실행 안 함)

```bash
# 1) 저장소 루트에서 한 번만
npm install

# 2) 실제 음성 준비 (필수 — audio/README.md 참고)
#    shorts/롱폼02_숏폼04/audio/롱폼02_숏폼04.mp3 (또는 .wav)

# 3) 오디오 길이에 맞춰 타이밍 자동 보정 (선택이지만 권장)
cd shorts/롱폼02_숏폼04
node scripts/fit-timeline-to-audio.mjs

# 4) 렌더링 (프레임 캡처 + mux)
./render/render.sh
# -> output/롱폼02_숏폼04.mp4 생성
```

내부적으로 `render.sh`는 `render/capture.mjs`(Playwright, 1080x1920/30fps
PNG 시퀀스 결정론적 캡처) → `ffmpeg`(PNG 시퀀스 + 오디오 mux, h264/aac)
순서로 동작합니다.

## 5. 기존 숏츠 파일 덮어쓰기 여부

**덮어쓰지 않았습니다.**

- 이 저장소(`dsf900601/intp-shorts`)에는 작업 시작 시점에 `README.md`
  한 줄 외 아무 파일도 없었습니다(기존 숏츠 1~3편 프로젝트 파일이
  저장소에 존재하지 않았음).
- 사용자가 업로드한 기존 숏츠 1~3편 mp4 3개는 **디자인 시스템을
  추출하기 위한 분석 자료로만 사용**했고, 저장소에 커밋하지 않았습니다.
- 새로 만든 파일은 모두 `shorts/롱폼02_숏폼04/`, `shared/design-system/`
  등 새 경로에 생성했고, 기존 파일을 수정한 것은 repo 루트 `README.md`
  뿐입니다(원래 한 줄짜리 플레이스홀더 문서였음).
- 출력 파일명은 `롱폼02_숏폼04.mp4`(폴더/파일명에 `롱폼02_숏폼04` 노출)로
  고정되어 있어 향후 숏폼05 등과도 경로가 겹치지 않습니다.
